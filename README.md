# ML-Based-Pre-Screening-and-Verification-Referral-for-Lithography-Hotspots-on-ICCAD-12-Benchmarks
This repository contains the reproducible implementation, saved result tables/plots, and IEEE-style report for Group G19's Digital Assignment II project.

1. Project idea

The system is a three-stage hotspot pre-screening pipeline:

ICCAD-12 layout image
        │
        ▼
Stage 1 — Lightweight CNN
        │
        ▼
Hotspot confidence score (0 to 1)
        │
        ▼
Stage 2 — Confidence-based referral
   ┌──────────┬──────────────┬───────────┐
   │  SAFE    │ NEEDS_CHECK  │   RISKY   │
   │ screen   │ verification │ flag HS   │
   └──────────┴──────────────┴───────────┘
        │
        ▼
Stage 3 — Baseline vs proposed analysis
        │
        ▼
Metrics + confusion tables + trade-off plots

The baseline uses one binary cutoff:

confidence < 0.50 → NHS

confidence >= 0.50 → HS

The proposed system uses three-way routing and tests:

0.30 / 0.70

0.20 / 0.80

0.10 / 0.90

For lower threshold L and upper threshold H:

C <= L → safe

L < C < H → needs_check

C >= H → risky

needs_check means the CNN is not trusted enough for an automatic decision, so the pattern is sent to detailed verification.

4. Environment

Install the dependencies in a virtual environment.

python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

If TensorFlow does not install for your current Python version, use a Python version supported by the TensorFlow release you install. A separate Python 3.12 environment is a practical fallback for older TensorFlow setups.

7. Important interpretation of the proposed results

The proposed system is not a new trained CNN. The CNN produces the same saved confidence scores; Stage 2 changes only the decision policy.

Also, the proposed system is fundamentally a 2×3 routing problem:

                 Proposed decision
Actual class    SAFE   NEEDS_CHECK   RISKY
--------------------------------------------
HS               ...       ...         ...
NHS              ...       ...         ...

A hotspot in safe is counted as an unchecked hotspot.

A hotspot in needs_check is not counted as a final detection success or failure because the downstream verifier has not yet been executed.

Therefore:

The proposed missed-hotspot rate is an unchecked-hotspot routing metric, not a final post-verification false-negative rate.

8. Confusion-matrix comparison

For a direct pooled comparison at 0.20/0.80:

Baseline binary false negatives: 154

Proposed hotspots screened as safe: 80

Reduction in dangerous unchecked cases: 74 patterns

Relative reduction from the pooled baseline FN count: 48.1%

For the proposed 2×2 safety-oriented visualization, needs_check + risky are grouped as attention, while safe is treated as automatic pass. This is only a routing comparison; it must not be interpreted as a final verified HS/NHS classification matrix.

9. Verification workload interpretation

At 0.20/0.80, the macro-average referral rate is 3.44%.

If every pattern would otherwise enter detailed verification, this routing policy would reduce the number entering that queue by a potential:

100% - 3.44% = 96.56%

This is a potential workload reduction, not a measured simulation-time reduction.

The saved pooled referral queue contains 2,217 patterns:

147 true hotspots

2,070 true non-hotspots

A future verifier should be used to determine how many of those referred patterns are actually confirmed as hotspots and to measure real runtime/cost.

10. Future work

The current CNN uses 64×64 input. Increasing input resolution and/or moving to a more standard/deeper CNN can be studied because aggressive downsampling may remove fine layout geometry that is useful for hotspot classification.

Other next steps:

integrate a lithography or trusted detailed verifier,

measure inference and verification runtime,

calibrate confidence scores,

choose thresholds on validation data,

repeat experiments across random seeds,

investigate stronger CNNs and higher-resolution inputs,

study data augmentation and transfer-learning alternatives,

analyze persistent confident errors.

11. Reference work

The supplied reference paper is:

A. Verma, K. Akhilesh Rao, and D. S. Hegde, “Lithography Hotspot Detection using Deep Learning,” IIT Bombay.

The reference work discusses the ICCAD-12 dataset, class imbalance, VGG16-based transfer learning, and a lightweight custom CNN. It reports an average validation balanced accuracy of 95.3% for its custom CNN and an average inference time of 6.3 ms on the reported evaluation setup.

Those numbers are not directly compared as test results with the present project because the models, splits/protocols, and evaluation procedures are different.
